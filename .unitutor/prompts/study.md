Language: English only.

One study session of a given length that mixes `/tutor` and `/repeat` in alternating blocks. `/study` only sequences; teaching and questioning rules stay those of `tutor.md` and `repeat.md`.

Arguments: hours (required, e.g. `/study 2.5`; if missing, ask once).

1. Run `python3 .unitutor/progress.py plan <hours>` (do not run `mark start` yet; it runs when the user writes "start", step 2. It starts the timing log; every `grade` logs one event and `plan` learns your minutes per topic from the gaps) (Windows: `python .unitutor\progress.py ...`). Do not read `progress.md` yourself. If it reports a missing `schedule.json`, tell the user to copy `.unitutor/schedule.example.json` and fill in the timetable, then continue with the plan as printed.
2. Show the plan as a compact table (Block | Type | Course / lecture | Topics | ~min) and add one line on what the "Not scheduled" counts mean (rule 0 = lecture with a tutorial within 24 h, always first; rule 1 = lectures from previous weeks still `new`; rule 2 = lectures whose tutorial is still ahead). If rule 2 topics are left unscheduled while a tutorial is within 48 h, say so plainly. Write the table and the "start" line in the final message of the turn, after all tool calls (including any wrap-up call); text written between tool calls gets collapsed in the UI and the user never sees the plan. Then stop and wait: do not start block 1 and do not teach or ask anything yet. End with one line telling the user to write "start" to begin. Only when the user writes "start": run `python3 .unitutor/progress.py mark start` (Windows: `python .unitutor\progress.py mark start`), then begin block 1.
3. TUTOR block (for Adversarial Machine Learning the topics are paper sections, taught from the week's Main Papers per the AML override in `AGENTS.md`): the listed topics are `new`, in order. For each, run steps 3-6 of `.unitutor/prompts/tutor.md` (one paragraph per reply, a question only on "question", the next topic only on "next", `grade ... seen` after each topic). Say in one line which lecture the block continues. The block ends after its last topic; the user's "next" after it opens the following block. Never start new topics beyond the block.
4. REPEAT block: each listed item is a due review. For each, run steps 3-5 of `.unitutor/prompts/repeat.md` (one question per reply, no Socratic follow-up, expected answer, coverage grade, `grade ...`, gaps log). Aim questions at the item's note. No new topics. A topic graded `partial`/`fail` is not retried inside `/study` (it is already due again via the ladder); topics taught earlier in this session are not quizzed in it.
5. Time is a planning estimate, not a clock: do not announce elapsed time. The user may say "skip block" (move on, nothing graded) or "stop"/`/end` (recap now).
6. When the last block is done, or on stop: run `python3 .unitutor/progress.py mark end`, then recap table (Course | Topic | old -> new status), say plainly which topics are exam-ready and which still have gaps, and give the remaining backlog from the plan's "Not scheduled" line in one sentence. Then stop.
